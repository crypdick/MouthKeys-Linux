# Upstream parity acceptance ledger

Objective: bridge **all bridgeable gaps** against
[BenevolentFutures/MouthKeys](https://github.com/BenevolentFutures/MouthKeys) commit
`d50ad008ecd6b734e8fb3e9ab7ee942e3f6e388d` (2026-11-01). Implementation audit: 2026-11-09,
with native smoke evidence recorded 2026-11-10 UTC. [README.md](README.md) is the usage guide;
this file is the canonical requirement/evidence ledger.

**The objective is not declared complete.** Implemented code, passing fakes, and actual library
inference are different evidence levels. No feature is excluded because an older Linux port lacked
it. Configurable cloud AI, Spoken Send, return-to-target, and media controls are supported, not
prohibited. Local dictation remains available; telemetry/update polling remain off. Desktop/i3
bindings are acceptable; integrated shortcuts are optional, lower-priority alternatives.

## Evidence levels

- **Implemented:** reachable application/CLI behavior exists, not an enum or placeholder.
- **Headless:** fake adapters, isolated XDG paths, algorithm fixtures, and offscreen Qt tests exercise
  the contract. They do not capture audio, alter the clipboard, synthesize keys, show windows,
  take focus, or play sounds.
- **Native functional smoke:** real installed model/processor/worker classes run on the existing
  WAV with locally constructed tiny random weights. [Recorded evidence](tests/native_smoke_evidence.json)
  and [reproducer](tests/smoke_native.py) cover Qwen/Cohere inference and NeMo streaming/file inference/
  actual word offsets. This proves integration, **not pretrained recognition accuracy or speed**.
- **Desktop / hardware / pretrained acceptance:** actual compositor/toolkit, microphone, clipboard,
  receiver, provider account, or authorized checkpoint is exercised. These checks remain pending
  unless a concrete result is recorded; passing headless tests does not promote them automatically.

## Pending evidence and genuine constraints

1. Complete [manual desktop/hardware checks](README.md#manual-desktop-and-hardware-checklist) on the
   actual X11/Wayland compositor and target toolkits. No live microphone, clipboard, focus, key,
   sound, or receiver action is authorized merely by running the test suite.
2. Pretrained checkpoint tests require already available artifacts or an explicit download request;
   gated terms/account access may need the user. Tiny smoke output is deliberately not reported as
   recognized text or an accuracy/latency benchmark.
3. Record real-model language coverage, speed/RAM and recognition quality; native model metadata
   and parameter/weight sizes do not establish runtime measurements. Never manufacture these values.
4. AT-SPI, portal, compositor virtual-key, and HID support differ by desktop/hardware. Where no
   supported destination evidence is available, copy/review fallback is a real limit, not permission
   to fabricate success. Implement available adapters before classifying a gap as external.
5. Apple frameworks cannot run natively on Linux; alternatives must provide the user-facing behavior.
   Byte-for-byte Swift compatibility and macOS notch visuals are not the acceptance criterion.

Keep this ledger aligned with source and concrete validation results. Leave the objective open until
each requirement has acceptance evidence or a specific genuine external blocker; implementation
breadth alone does not complete it.
